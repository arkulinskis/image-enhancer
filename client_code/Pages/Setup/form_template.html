Two sides to set up: your PC (it does the painting) and your apps (they send pictures and get them back).

Your PC

About 20 minutes, most of it downloading.

The PC runs ComfyUI with FLUX.2 [klein] 4B, an open image-editing model (Apache 2.0, fine for commercial apps) that repaints a picture from a plain instruction in 4 steps. It needs an NVIDIA graphics card with 8 GB or more, about 15 GB of free disk, Python 3.10 to 3.12 and Git. A small worker script links ComfyUI to this app through Anvil Uplink: the app hands it one picture at a time and it hands back the result.

Switch on Uplink in Anvil

In the Anvil editor for this app: the + (Add feature) button → Uplink → Enable the Server Uplink. Copy the key it shows (it starts with server_). It is a password for the whole app: keep it on the PC only.

Put the worker on the PC

Download the app's files as a zip, unzip them anywhere (for example C:\ImageEnhancer) and open the worker folder. Or with Git:

git clone https://github.com/arkulinskis/image-enhancer.git C:\ImageEnhancer

Install ComfyUI and the model

In the worker folder, right-click setup_comfyui.ps1 → Run with PowerShell. It installs ComfyUI next to the worker (its own Python environment with the right PyTorch for NVIDIA cards) and downloads the three model files, about 11.6 GB. Run it again any time: it skips what is already there and updates ComfyUI.

powershell -ExecutionPolicy Bypass -File setup_comfyui.ps1

Start the worker

Double-click start_worker.bat. The first time it asks for the Uplink key and saves it in config.json (never uploaded anywhere). It starts ComfyUI if it isn't running, connects, and the lamp above turns green. Keep the window open; close it to stop. To start it with Windows, put a shortcut to start_worker.bat in shell:startup.

Try it

Send a picture from the Test bench. The first one takes longer (the model loads into the graphics card); after that a 1-megapixel picture takes about 20 to 60 seconds on an 8 GB laptop card.

No GPU yet? start_worker.bat --backend classic runs a simple built-in filter instead of the model, so you can test the whole round trip.

Your apps

Every call needs a key from Apps & keys.

The API lives at this address. Send the key in the Authorization header, never in the address.

POST /jobs
Send a picture: JSON with image (base64) or image_url, the picture's bytes, or a multipart form. Answers 202 with the job: its id, position and eta_seconds.
GET /jobs/<id>
Where it is: status (queued, working, done, failed, cancelled), position, estimated finish (eta_at), and result_url once done. Add ?wait=20 to hold the answer until it finishes, up to 20 s.
GET /jobs/<id>/result
The finished picture itself.
GET /queue
How long the queue is, whether the PC is online, and when a picture sent now would be ready.
GET /styles
The styles to choose from.
GET /jobs
Your app's recent jobs (?status=open, done ...).
POST /jobs/<id>/cancel
Cancel a picture that hasn't started.

Options you can send with a picture: style (required), prompt (extra words), fidelity (loose, balanced, strict), megapixels (0.25 to 2, default 1), size (model, or source to get your picture's size back), format (png, jpeg, webp), seed, ref (your own id, returned with the job) and callback_url (https; called when it's done).

From another Anvil app (Python, server code)

Put the key in that app's Secrets as image_enhancer_key, and copy clients/enhancer_client.py into its server code. Then:

from . import enhancer_client as enhancer

job = enhancer.submit(drawing_media, "kids_book", ref=str(order_id))   # {"id": "job_...", "eta_seconds": 95, ...}
...
job = enhancer.status(job["id"])            # or enhancer.wait(job["id"], timeout=25) in a background task
if job["status"] == "done":
    row["styled"] = enhancer.result(job["id"])   # an Anvil Media, ready for a media column

From anything else (curl)

curl -X POST "API_BASE/jobs?style=scifi&fidelity=strict" \
  -H "Authorization: Bearer $IE_KEY" -H "Content-Type: image/png" \
  --data-binary @drawing.png

curl -H "Authorization: Bearer $IE_KEY" "API_BASE/jobs/job_xxxxxxxx?wait=20"

JavaScript (Node 18+, server side)

const res = await fetch("API_BASE/jobs", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.IE_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ image: fs.readFileSync("drawing.png").toString("base64"), style: "anime", ref: "card-42" }),
});
const { job } = await res.json();   // job.id, job.position, job.eta_seconds

When a picture is done (webhooks)

Send callback_url and the service POSTs {"event": "job.done", "job": {...}} (or job.failed) there. Check it really came from here with the key's webhook secret:

import hashlib, hmac

def from_image_enhancer(raw_body: bytes, signature_header: str, secret: str) -> bool:
    good = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(good, signature_header or "")   # header: X-Enhancer-Signature

Keys are for servers only: never put one in a web page or a phone app, where anyone could read it.
